[English]
Implements DESIGN.md v1.2: page-based I/O, aggregate functions, and ORDER BY.

Storage — 4KB slotted pages
- Rows are serialized into fixed-size 4KB slotted pages instead of a flat array
  of live Value structs (header + slot directory growing front, tuple data
  growing from the back)
- INT is 8 bytes, TEXT is u16 length + bytes, NULLs via a null bitmap
- Scans reconstruct rows by deserializing tuples through a cursor
  (table_cursor_next)
- A row must fit within one page; oversized rows are rejected on insert
- Added value_text_n to rebuild TEXT from non-NUL-terminated bytes

Aggregates — COUNT / SUM / AVG / MIN / MAX
- COUNT(*), COUNT(col), SUM/AVG (INT), MIN/MAX (INT numeric, TEXT lexicographic)
- Honour WHERE; empty-set semantics: COUNT = 0, others = NULL
- Reject mixing aggregates with plain columns; SUM/AVG require INT; unknown
  function names are a parse error

ORDER BY
- Multiple keys, each ASC (default) / DESC, NULLs sort first
- May order by columns not in the projection (rows are materialized fully, then
  sorted, then projected)

Tooling / docs
- tests: added test_aggregates / test_order_by / test_pages (make test passes,
  10107 checks)
- make memcheck: valgrind clean, 0 leaks / 0 errors (covers serialize +
  materialize paths)
- bench: added aggregate (5 funcs) and order-by (full sort) workloads
