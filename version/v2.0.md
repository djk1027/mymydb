설계 — 오브젝트 모델
- 모든 구조를 오브젝트(object id + type)로 관리. 타입은 db, table 두 가지.
- 오브젝트 종류별 구조체: Object 헤더를 임베드한 Database / Table.
- 오브젝트 종류별 소스 파일 분리:
  src/storage/{object,value,pager,table,database,instance}.{h,c}
  (storage.h는 이들을 묶는 우산 헤더)
- 인스턴스(Instance)가 논리적 database 다수를 소유. CREATE DATABASE / USE 추가.
  시작 시 기본 database 'main' 생성.

설계 — 블록/익스텐트/지속성
- page → 8K Block으로 개명(BLOCK_SIZE 8192).
- 블록 할당은 익스텐트 단위: 첫 익스텐트 8 Block, 이후 더블링(8,16,32,...).
  익스텐트를 파일에 연속 배치해 오브젝트 내 시퀀셜 스캔의 LBA 연속성 확보.
- page id = (db_id, object_id, sequence). 오브젝트별 유니크, 중복 없음.
- 스토리지 저장: 페이지(블록) 단위. 인스턴스를 파일로 열면(./mymydb <file>)
  블록 0=슈퍼블록, 연속 카탈로그 런, 익스텐트 데이터 블록으로 구성.
- 체크포인트: dirty 블록 + 카탈로그 + 슈퍼블록을 기록. 카탈로그는 용량 내면
  제자리 갱신. executor가 성공한 변경(CREATE/INSERT/DELETE/CREATE DATABASE)
  마다 체크포인트 실행(추후 버전에서 체크포인트 관리 메커니즘 예정).
- 복원: 파일 재오픈 시 슈퍼블록→카탈로그→데이터 블록을 읽어 오브젝트 트리 재구성.
- 인자 없이 실행(db_new)하면 인메모리 인스턴스(pager=NULL, 체크포인트 no-op)라
  기존 테스트/벤치 성능 회귀 없음.

[English]
Implements DESIGN.md v2.0: object-based storage redesign, disk persistence, DELETE.

Feature
- DELETE FROM t [WHERE ...]. Rows are tombstoned (slot offset 0) and skipped by
  scans; no WHERE deletes all rows.

Design — object model
- Everything is an object (object id + type); types are db and table.
- Per-type structs: Database / Table each embed an Object header.
- Source split per object type:
  src/storage/{object,value,pager,table,database,instance}.{h,c}
  (storage.h is an umbrella header).
- An Instance owns multiple logical databases; CREATE DATABASE / USE added; a
  default database 'main' is created at startup.

Design — blocks / extents / persistence
- Renamed page -> 8K Block (BLOCK_SIZE 8192).
- Extent-based allocation: first extent 8 blocks, then doubling (8,16,32,...);
  extents are laid out contiguously so an object's blocks stay LBA-contiguous
  for sequential scans.
- page id = (db_id, object_id, sequence): unique per object, never duplicated.
- Per-block storage: opening an instance with a file (./mymydb <file>) lays out
  block 0 = superblock, a contiguous catalog run, and extent data blocks.
- Checkpoint writes dirty blocks + catalog + superblock; the catalog is updated
  in place while it fits. The executor checkpoints after each successful
  mutation (CREATE/INSERT/DELETE/CREATE DATABASE); checkpoint-management policy
  is deferred to a later version.
- Reload: reopening a file reads superblock -> catalog -> data blocks and
  rebuilds the object tree.
- Running with no argument (db_new) is a memory-only instance (pager == NULL,
  checkpoint is a no-op), so existing tests/benchmarks keep their performance.

Tooling / docs
- tests: test_blocks (8K/extents/oversized-row rejection), test_delete,
  test_databases, test_persistence (save -> reopen -> reload, deletes stay
  gone, post-reload mutations persist). make test passes (10158 checks);
  make memcheck is valgrind-clean (0 leaks / 0 errors).
- CLI: ./mymydb [datafile] (durable when a file is given), a .databases meta
  command, banner/help bumped to v2.0.
- Marked DESIGN.md v1.3 / v2.0 headlines (완료) per AGENT.md; spec text unchanged.
- git commit / merge performed by the user.
